# Payer Policy Intelligence — Hackathon Submission

## Overview
End-to-end GenAI pipeline that ingests payer Prior Authorization (PA) policy PDFs, extracts 12 structured clinical parameters per (Filename, Brand) pair, computes an Access Quality Score (0–100), and outputs `result.csv` + an interactive HTML dashboard.

---

## Model Declaration (Mandatory)

| Pipeline Step | Model Used |
|---|---|
| PDF text extraction | No LLM — `pdfplumber` / `PyMuPDF` |
| Brand detection & segmentation | No LLM — regex keyword scan |
| Parameter extraction (text ≤ 8,000 chars) | `llama-3.1-8b-instant` |
| Parameter extraction (text > 8,000 chars) | `llama-3.3-70b-versatile` |
| Parameter extraction (JSON parse retry) | `llama-3.3-70b-versatile` |
| Access Quality Score computation | No LLM — deterministic Python |
| Output assembly & validation | No LLM — pandas |
| HTML dashboard generation | No LLM — pure Python/Chart.js |

**Final submission uses only:** `llama-3.1-8b-instant` and `llama-3.3-70b-versatile` via Groq API.

## Quick Start

### 1. Install dependencies
```bash
pip install -r requirements.txt
```

### 2. Set your Groq API key
Either add it to a `.env` file:
```
GROQ_API_KEY=gsk_...
```
Or set it as an environment variable:
```powershell
$env:GROQ_API_KEY = "gsk_..."
```

### 3. Run the pipeline
```bash
# Option A — Python script (recommended)
python pipeline.py

# Option B — Jupyter notebook
jupyter notebook notebooks/full_pipeline.ipynb
```

### 4. Outputs
| File | Description |
|---|---|
| `outputs/result.csv` | **Final submission file** — 1 row per (Filename, Brand) |
| `outputs/score_breakdown.csv` | Per-component score contributions for transparency |
| `outputs/extraction_log.json` | Groq response cache — prevents redundant API calls on re-runs |
| `outputs/dashboard.html` | Interactive payer-by-payer access score heatmap |
| `outputs/ingestion_errors.log` | PDFs with extraction issues (if any) |

## Pipeline Stages

| Stage | Description |
|---|---|
| **S1 — Ingestion** | `pdfplumber` primary extractor; `PyMuPDF` fallback for scanned/complex pages |
| **S2 — Segmentation** | Loads (Filename, Brand) job list from Submissions sheet; segments text to brand-relevant sections |
| **S3 — Extraction** | Groq API with SHA256-keyed disk cache; structured JSON prompt for 12 parameters + confidence + exclusion flag |
| **S4 — Scoring** | Deterministic Python scoring rubric; exclusion override sets score = 0 |
| **S5 — Output** | Validation assertions → `result.csv` + `score_breakdown.csv` + `dashboard.html` |

## Scoring Rubric Summary

| Component | Max Points |
|---|---|
| Age eligibility | 10 |
| Conventional step therapy count | 20 |
| Biologic step therapy count | 20 |
| Step therapy trial duration | 10 |
| TB test requirement | 10 |
| Prescriber restriction | 10 |
| Initial authorization duration | 10 |
| Reauthorization duration | 10 |
| **Total** | **100** |

## Rate Limit Management

| Model | RPD Limit | Usage |
|---|---|---|
| `llama-3.1-8b-instant` | 14,400 | All standard extractions (text ≤ 8K) |
| `llama-3.3-70b-versatile` | 1,000 | Long docs (>8K) + JSON parse retries only |

All Groq responses are cached to `outputs/extraction_log.json`. Re-running the pipeline does **not** burn additional API quota.

---

## Reproducibility

The pipeline is fully reproducible end-to-end:
- No manual steps required
- Deterministic scoring (temperature=0 for all LLM calls)
- Disk-cached responses for identical re-runs
- All paths relative to `BASE_DIR = Path(__file__).resolve().parent` (the project root folder)
