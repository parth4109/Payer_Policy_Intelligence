# Payer Policy Intelligence — Hackathon Submission

## Overview

End-to-end GenAI pipeline that ingests payer Prior Authorization (PA) policy PDFs, extracts
12 structured clinical parameters per (Filename, Brand) pair, computes an Access Quality
Score (0–100), and outputs `result.csv` + an interactive HTML dashboard.

**Result summary (v3 — final):** 79 rows across 70 PDFs and 15 brands. Mean access score
77.6 / 100. 58 of 79 policies score ≥ 75 (high access). 2 drugs explicitly excluded
(score = 0).

---

## Model Declaration (Mandatory)

| Pipeline Step | Tool / Model |
|---|---|
| PDF text extraction | No LLM — `pdfplumber` (primary), `PyMuPDF` (fallback) |
| Brand detection & segmentation | No LLM — regex keyword scan + omnibus-doc handler |
| Parameter extraction — text ≤ 8,000 chars | `llama-3.1-8b-instant` via Groq |
| Parameter extraction — text > 8,000 chars | `llama-3.3-70b-versatile` via Groq |
| Parameter extraction — JSON parse retry | `llama-3.3-70b-versatile` via Groq |
| Access Quality Score computation | No LLM — deterministic Python rubric |
| Output assembly & post-processing | No LLM — pandas |
| HTML dashboard | No LLM — pure Python + Chart.js |

**All LLM calls use Groq API only:** `llama-3.1-8b-instant` and `llama-3.3-70b-versatile`.
No paid APIs, no local GPU, no proprietary models.

## Quick Start

### 1. Install dependencies

```bash
pip install -r requirements.txt
```

### 2. Set Groq API key

```bash
# Option A — .env file (recommended)
echo "GROQ_API_KEY=gsk_..." > .env

# Option B — environment variable (Windows PowerShell)
$env:GROQ_API_KEY = "gsk_..."

# Option B — environment variable (Linux / macOS)
export GROQ_API_KEY="gsk_..."
```

### 3. Place PDF files

Copy all PA policy PDFs into the `Data/` folder. File names must follow the pattern
`{file_id}.pdf` (e.g. `330109-4880941.pdf`).

### 4. Run the pipeline

```bash
# Recommended — standalone script
python pipeline.py

# Alternative — Jupyter notebook
jupyter notebook notebooks/full_pipeline.ipynb
```

### 5. Outputs

| File | Description |
|---|---|
| `outputs/result.csv` | **Final submission file** — 1 row per (Filename, Brand) |
| `outputs/score_breakdown.csv` | Per-component score breakdown for transparency |
| `outputs/extraction_log.json` | Groq response cache — prevents redundant API calls on re-runs |
| `outputs/raw_texts_cache.json` | Extracted PDF text cache — prevents re-ingestion on re-runs |
| `outputs/dashboard.html` | Interactive payer access score heatmap with brand filters |
| `outputs/ingestion_errors.log` | PDFs with extraction issues, if any |

## Pipeline Architecture

### Stage 1 — PDF Ingestion

`pdfplumber` extracts text with word-position tolerance tuning. `PyMuPDF` serves as
fallback for scanned or complex-layout pages. All extracted text is cached to
`raw_texts_cache.json` so subsequent runs skip re-ingestion entirely.

### Stage 2 — Brand Segmentation

Jobs (Filename, Brand) pairs are loaded from the Submissions sheet in
`PA_Business_rules_pc.xlsx`. For each job the pipeline segments the full document text to
the most relevant portion for that brand:

- **Standard documents:** finds the brand-named section header and extracts the block up to
  the next brand's header.
- **Omnibus Medicaid documents** (e.g. state Medicaid omnibus PA criteria covering dozens of
  drugs): detects the shared biologic approval criteria block (plaque psoriasis approval
  flow + renewal criteria + TB/universal criteria) since no per-brand section header exists.
- **Fallback:** scores paragraphs by brand-keyword density and takes the top-scoring chunks
  up to 9,000 characters.

New PDFs not listed in the Submissions sheet are auto-detected by keyword scan.

### Stage 3 — LLM Parameter Extraction

A single structured prompt extracts all 12 parameters in one API call per (Filename, Brand)
job. All responses are SHA256-keyed and cached to `extraction_log.json`; re-runs cost zero
additional API quota.

**Key prompt design decisions:**

- **Step counting:** explicit OR-path minimum logic — if any approval pathway requires only
  disease-severity documentation (e.g. ≥10% BSA) with no prior therapy, step counts are 0.
  Phototherapy is never counted in biologic or conventional step totals.
- **Phototherapy AND/OR detection:** explicit examples distinguish mandatory AND-lists (every
  item must be satisfied → Yes) from OR-lists (patient picks one option → No).
- **Auth duration guard:** the model is instructed to distinguish a trial duration embedded
  in step therapy language (e.g. "biologic for at least 3 months") from an explicit
  authorization period ("authorization of X months"). Only the latter is extracted.
- **Aetna CPB-style payers:** instructed to output "Unspecified" when no auth duration is
  stated inline, rather than inferring 12 months.

**Rate limit handling:** a TPM-aware rolling throttle tracks token usage in a 60-second
window and sleeps before calls that would exceed 85% of the 6,000 TPM free-tier ceiling.
On 429 errors the pipeline parses Groq's retry-after time, sleeps exactly that duration,
and retries up to 3 times with exponential back-off before falling back to the other model.

### Stage 4 — Access Quality Score

Fully deterministic Python rubric (no LLM). Scores reflect how favourable a payer policy
is for the pharma brand, not model accuracy.

| Component | Max pts | Scoring logic |
|---|---|---|
| Age eligibility | 10 | ≥6 yrs = 6 pts · ≥12 = 8 · ≥18 = 10 · >18 or ≥21 = 5 |
| Conventional step count | 20 | 0 steps = 20 · 1 = 15 · 2 = 8 · ≥3 = 0 |
| Biologic step count | 20 | 0 steps = 20 · 1 = 12 · 2 = 5 · ≥3 = 0 |
| Step therapy duration | 10 | No steps or ≤3 months = 10 · ≤6 months = 5 · >6 = 0 |
| TB test required | 10 | Yes = 5 · No = 10 |
| Prescriber restriction | 10 | None/Not specified = 10 · Preferred = 7 · Required = 3 |
| Initial auth duration | 10 | ≥12 months = 10 · ≥6 = 5 · <6 = 0 · Unspecified = 7 |
| Reauth duration | 10 | Same logic as initial auth |
| **Total** | **100** | Explicit exclusion → score = 0 (false-exclusion guard applied) |

**Score interpretation:**
0 = No access (drug excluded) · 25 = Restricted vs FDA label · 50 = Parity with FDA label ·
75 = Preferred vs FDA label · 100 = Best possible access / no restrictions.

### Stage 5 — Output Assembly

Post-processing rules applied before writing CSV:

- Age normalised to `>= N` format (unicode ≥ replaced, trailing "years" / "y" stripped).
- Phototherapy display: always `Yes` or `No` — never `N/A`, which pandas silently converts
  to NaN on CSV read.
- Quantity limits: dosing schedules (mg at weeks, every N weeks) filtered out; only explicit
  `quantity limit` statements retained; defaults to `Per FDA label`.
- Auth duration: a trial-context guard resets durations ≤ 4 months to `Unspecified` when
  that number appears only as a step-trial duration in the step text.
- False-exclusion guard: if `exclusion_flag=True` but the three core fields (qty, step,
  age) are not all `N/A - Drug Excluded`, the flag is treated as an LLM error and the row
  is scored normally.
- Phototherapy generic step correction: if phototherapy=Yes and the step text contains an
  AND-list (either numbered or prose with ≥3 AND conjunctions), one generic step count is
  subtracted to remove the phototherapy item the model incorrectly included.
- CSV written with `na_rep=""` so residual `None` values write as empty strings rather than
  literal `nan` text.

## Rate Limit Reference

| Model | Free tier RPD | Free tier TPM | Role in pipeline |
|---|---|---|---|
| `llama-3.1-8b-instant` | 14,400 | 6,000 | All standard extractions |
| `llama-3.3-70b-versatile` | 1,000 | 6,000 | Long docs (>8K chars) + retries |

The pipeline's rolling TPM throttle targets 85% of the 6,000 token/minute ceiling
(5,100 effective TPM). To increase throughput on a paid Dev tier, set `TPM_LIMIT = 30000`
at the top of the rate-limit section in `pipeline.py`.

## Reproducibility

| Property | Implementation |
|---|---|
| Deterministic LLM calls | `temperature=0` for all Groq calls |
| No re-extraction on re-run | SHA256-keyed disk cache in `extraction_log.json` |
| No re-ingestion on re-run | PDF text cached in `raw_texts_cache.json` |
| No hardcoded paths | All paths relative to `BASE_DIR = Path(__file__).resolve().parent` |
| No manual steps | Single command: `python pipeline.py` |
| Dependencies pinned | `requirements.txt` with fixed versions |

To force a full re-run from scratch, delete `outputs/extraction_log.json` and
`outputs/raw_texts_cache.json` before running.

To re-extract specific rows only (e.g. to fix stale cache entries), delete the
corresponding keys from `extraction_log.json` while leaving all other entries intact.
The pipeline will re-call the API for those rows only and use the cache for everything else.
